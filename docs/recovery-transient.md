# 间断恢复瞬态优化

2026-11-10，在 `c135c13` 的间断通知机制上调整解码器恢复。实板和离线数据见 [验证记录](../artifacts/recovery-transient-validation.json)。声学复验改用低音量中文合成人声；早期纯音对照作为已有证据保留，不重复播放。

## 原因与修改

从上轮实板 RTT 提取的真实 PDM 片段具有约 0.01144 的平均直流分量。原解码器重置会连同去直流状态一起清零，把该偏置转为衰减脉冲。重复相同 PDM 周期的主机重放中，旧重置后首 50 ms 的峰值为 433 LSB，新恢复为 9 LSB；该对照在数字增益之前，不是整机声压或主观听感结果。

`Decoder::reset()` 现在：

1. 保存 `previous_input - HP_POLE * previous_output`，即下一采样所需的慢变直流估计。
2. 清空 CIC、FIR、抽取相位和高通信号历史；保留的只有直流估计。
3. 持续处理并输出等长零采样，预热 196 个 PDM 半字，约 3.0625 ms。
4. 预热完成后，对高通输出做 64 samples /4 ms 线性淡入。

采样数、队列容量、重采样控制、USB 格式、正常连续处理以及启动校准规则不变。连续输入和正常启动不启用恢复预热 / 淡入。

主机测试覆盖正负直流偏置、带抖动的合成音调、重复间断、捕获历史清除、固定抽取数、稳态幅度和相对信噪比。总计 36 个 Rust 测试及 5 个 Python 离线测试通过；默认检查脚本和诊断 / 原声 / PDM 模式、主机解码示例 Clippy 均通过。`decode_pdm` 示例可用 `--gap-at-word N` 重放重置。

## 已有相同播放文件的实板对照

诊断版继续使用相同的三次 10 ms 采集暂停，实际触发三次 DMA 覆盖。PC 播放 WAV 字节与上轮完全一致。两轮稳态录回音量不同，声学环境和 Windows 端点增益未独立控制，因此主要对比各轮自己的“恢复峰值 / 稳态 RMS”，不将总体音量差当作改善。

| 注入 | 旧峰值 / 新峰值（LSB） | 旧峰值与稳态 RMS 之比 / 新比值 | 比值降低 | 旧 / 新接近静音区间 |
| --- | --- | --- | --- | --- |
| 1 | 5858 /1193 | 10.33 /1.52 | 约 85% | 28 /35 ms |
| 2 | 9200 /1156 | 16.55 /1.49 | 约 91% | 29 /36 ms |
| 3 | 4840 /1146 | 8.66 /1.51 | 约 83% | 29 /36 ms |

接近静音按 Windows 录回信号的 1 ms RMS <2 LSB 定义。新增约 7 ms 包括滤波器预热 / 淡入带来的影响，不是严格的端到端延迟测量。恢复后的稳态音量与本轮间断前相近；额外 USB / DMA 硬件错误、PCM 溢出、输出欠载和削顶均为零。

正常版完成 60 秒录音、5 次重开和退出调试器后的 15 秒独立录音，无削顶；正常版七项可见 DMA / PCM / USB 错误计数为零，连续和独立录音无启动 200 ms 后的全零毫秒。220 秒 USB 轮询中，正常版完成校准后未观察到枚举变化。

## 低音量人声复验

应用户要求停止纯音测试，使用 Windows `Microsoft Huihui Desktop` 将中文朗读合成为 WAV，再将数字峰值限制到 1000 LSB（约 -30.3 dBFS），通过 PC 默认输出播放。

- 35 秒语音录音期间实际注入三次 DMA 覆盖，随后继续采集；无额外 USB / DMA 硬件错误、PCM 溢出或输出欠载，无削顶。
- 恢复无故障注入的正常固件，退出调试器后完成 12 秒独立语音录音，无削顶。
- 人声录音和原始朗读 WAV 保存在 `captures/recovery-transient-20261110/`。合成人声覆盖朗读和停顿，不等同于真人轻声 / 气声语音库或主观可懂度验收。

结束时板上保留新正常 `adaptive-noise` 固件，`audio-gap-test` 关闭，调试器退出。该映像静态 SRAM 29800 bytes，Flash 93456 bytes。

保留旧直流估计适用于同一麦克风的采集间断；未验证长间断期间偏置突然变化的情况。本轮不宣称完全无爆音、补回丢失语音或改善语音可懂度，也不代替长时、睡眠、物理插拔和严格 WCET / 栈高水位测试。
