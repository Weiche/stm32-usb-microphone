# 启动校准与轻声学习保护

2026-11-10，保留先前的间断恢复与瞬态修复，调整启动校准及可选自动跟踪。离线证据见 [校准与学习保护记录](../artifacts/calibration-guard-validation.json)，后续人声实板证据见 [硬件复验记录](../artifacts/calibration-guard-hardware-validation.json)。离线记录保留生成时尚未烧录的状态；后续烧录和板上结果单独记录，不覆盖原证据。

## 使用与状态

启动 / 手动重校准后，保持环境正常并安静至少约 5 秒；活动可能延长校准。USB 音频在校准期间继续走具有相同延迟的旁路。校准完成后红灯熄灭，开启降噪时橙灯亮。

- 红灯常亮：预热或积累候选背景数据。
- 红灯闪烁：检测到不可信活动后，正在等待安静再继续。
- 没有到时强制完成的兜底；持续活动时允许一直处于未就绪，避免把明显语音固定成噪声谱。

默认构建采用新的启动校准，校准后的谱仍固定。`--features adaptive-noise` 才启用自动跟踪及新增轻声学习保护；12 dB 降噪上限、数字增益、USB 格式和模块延迟不变。

## 启动校准

1. 略过最初 63 hops /504 ms。
2. 每段最多 32 hops /256 ms 先暂存功率谱，满足检查后才加入正式累积。
3. 在 125～4000 Hz 频带观察多峰音调结构和能量突变；检测活动时丢弃整段尚未提交的数据，并等待至少 63 hops。
4. 段内最大 / 最小能量超过 10 倍时丢弃该段。较宽门限允许真实房间噪声的正常起伏，较快突变由另一项检查处理。
5. 累积 500 个获准帧后取均值。已接受的干净片段可保留，活动片段不计入进度；重新校准或未完成时发生输入间断会从头开始。

RTT 保留 `calibration_frames`（获准帧数，完成为 500），增加 `rejected_frames`（丢弃的候选帧，不含预热及等待）、`hold_frames`（剩余等待帧）和 `calibration_blocked`。这些字段描述谱估计的保护状态，不是人声识别结果。

## 轻声学习保护

原有 250～4000 Hz 粗能量保护保留。新增 125～4000 Hz 的逐频点观察，以 `0.02` 系数平滑，约 400 ms 时间常数；对照初始谱，同时用全带公共功率变化归一化，使适度宽带背景升降仍可学习。

某频点的平滑功率超过归一化参考的 1.5 倍时积累票数，达到 8 票后暂停学习。投票会在异常消失时逐步衰减，保护解除后仍等待 504 ms。粗能量保护已触发时，重置慢观察器，避免大声语音的历史额外拖长恢复。

保护的对象是自动噪声谱更新：它不会自动提高麦克风增益，也不保证保住所有低信噪比气声 / 无声辅音。持续音调背景也可能暂停跟踪；这是保守启发式，未移植训练好的 VAD。

## 同输入离线结果

同一份中文合成语音与确定性噪声分别输入修改前后的 Rust DSP；所有生成音频仅保存文件，不播放。

| 启动输入 | 旧版就绪时间 | 新版就绪时间 | 新谱相对独立背景谱总功率 |
| --- | --- | --- | --- |
| 安静随机背景 | 4.504 s | 4.504 s | 相同 |
| 开头说话 6 s，随后安静 | 4.504 s（说话尚未结束） | 10.624 s | 约 1.002 倍；旧版约 80 倍 |
| 先安静 2 s，再说话 4 s | 4.504 s（说话尚未结束） | 8.256 s | 约 1.003 倍；旧版约 100 倍 |
| 连续说话 16 s | 4.504 s | 未完成，接受 160 帧 | 未生成最终谱 |
| 录回的真实房间背景片段 | 4.504 s | 5.144 s | 与旧谱接近 |

同一低信噪比合成谐波活动区间内，自动谱更新从 2487 hops 降到 25 hops；同一小声中文语音请求区间从 400 降到 173 hops。后者包含自然停顿，不能把帧数下降解释为语音识别准确率。已知合成语音参考的重建误差没有劣化，固定预计算谱模式的输出逐样本一致。

适度合成背景功率升至 2.25 倍时仍跟随至约 2.26 倍，残留背景相对固定谱额外降低约 2.19 dB。它不是受控风扇变速实测。

41 个 Rust 测试、默认构建 / Clippy 和两套数值对照已通过。自动版静态 SRAM 31388 bytes，Flash 100480 bytes；短时工作量观测见下节，严格 WCET 和栈峰值仍未测量。

## 低音量人声实板复验

用户重新插拔 CN1 后，ST-LINK 恢复连接；读回 93456 bytes 应用映像，与上一版恢复修复固件哈希一致，已保存备份。启用写入校验烧录与离线审查哈希相同的 `adaptive-noise` 候选版，不含 `audio-gap-test`，全程没有播放纯音。

- 观察到启动日志后立即播放约 6 秒低音量中文合成人声，数字峰值 1000 LSB。RTT 观察到等待安静状态，丢弃 80 个候选帧，约 8 秒时完成 500 帧校准。时间为主机观察启动日志后的近似值；这验证了保护触发和延后完成，不能证明现场噪声谱完全没有语音成分。
- 完成 14 秒启动录音、24 秒正常 / 较小音量 / 停顿录音及调试器退出后的 12 秒独立录音。三份录音均无削顶、无启动 200 ms 后的全零毫秒。
- 正常播放峰值 1000 LSB，较小音量片段为 250 LSB。该片段约 5 个每秒观测中，保护为真，更新计数保持 534；播放源静音片段也观察到保护，房间未做声学控制，不能把这些样本当作 VAD 准确率或误报率。
- 七项可见 DMA / PCM / USB 错误计数均为零。正常关闭流产生的 2 次 `disabled`、32 个 `discarded_samples` 不作为持续传输故障。
- 31 个已就绪、正在录音的统计窗口中，DSP + 包准备工作量中位数为墙钟预算的 51.7%，最大 52.3%；它不是完整 CPU 利用率。最长观测 FFT hop 1367 us、解码 365 us、包准备 92 us，均不是严格 WCET。
- 110 秒 USB 轮询完成 78 次查询，校准就绪后未观察到设备变化；短暂变化可能漏检。

结束时保留该固件运行，调试器已退出、播放已停止。原始 WAV、RTT、Flash 备份和执行脚本保存在本地 `captures/calibration-guard-20261110/`；红灯闪烁的实物视觉效果和真人轻声可懂度尚未验收。

## 复验

```powershell
.\tools\check.ps1
python tools/validate_adaptive_noise.py --output-dir captures/new-tracking-test
# before.exe 是修改前、支持 startup 与 --profile-out 参数的主机 denoise_pcm 副本
python tools/validate_calibration_guard.py --output-dir captures/new-startup-test --before-executable path/to/before.exe --speech-wav path/to/mono-s16-speech.wav
```

可追加 `--room-noise-wav`；该选项取输入录音的 0.25～1.25 s，调用者须保证这段只有背景。报告保存输入 / 可执行文件哈希、逐 hop CSV、PSD 与输出 WAV。原始样本和基线可执行文件留在本地 `captures/calibration-guard-20261110/`，不随仓库分发。

谱结构与能量检查不能可靠区分所有人声和噪声，特别是低信噪比宽带辅音、平稳元音和多音调背景。仍可能保守地暂停正常背景学习。当前只有短时人声实板复验，没有真人轻声可懂度评分、受控风扇变速、8 小时稳定性、物理插拔 / 睡眠恢复或栈峰值验收。
